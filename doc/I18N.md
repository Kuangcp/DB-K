# db-k 国际化（i18n）设计

> 目标：界面文案支持 **简体中文（zh）/ English（en）**，默认跟随系统，可手动切换并持久化。
> 本文是设计 + 迁移计划；落地规则以 `AGENTS.md` 的「国际化（i18n）★ 必读」为准（冲突时以 AGENTS.md 为准）。

---

## 1. 目标 / 非目标

### 目标

1. 支持 zh、en 两种语言；启动默认跟随系统 locale（`Locale.getDefault()`；zh 系 → 中文，其余 → 英文）。
2. 设置窗口可切换语言，**即时生效（不重启）**，重启后恢复。
3. 全分层可用：`app / tree / db / engine / jdbc / redis / es` 都能取到文案，且不破坏
   「`jdbc`/`redis`/`es`/`engine`/`tree`/`db` 禁止 import compose/coroutines」的硬约束。
4. 新功能必须同时提供两种语言；缺 key / 空文案由测试拦截，不靠人肉 review。
5. 与「状态即 snapshot」哲学一致：语言本身是一个 snapshot 状态，切换驱动 UI 重组。

### 非目标（明确不做）

- 不翻译：**日志**（`Logger.*`）、**冒烟自检输出**（`*Smoke.kt` 的 stdout）、SQL 关键字/方言语法、
  数据源品牌名（PostgreSQL / MySQL / Redis…）、数据库对象名 / 用户数据 / SQL 正文。
- 不做 RTL、不做完整 CLDR 复数/性别规则（当前仅 zh/en，复数用 one/other 两 key 即可）。
- 不做日期/数字本地化（沿用 JVM 默认与现有格式化）。
- 不本地化数据库返回的错误信息（驱动/服务端语言由其自身决定，原样展示）。

## 3. 方案选型

| 候选 | 说明 | 结论 |
|---|---|---|
| A. Compose `components-resources` | `composeResources/values*/strings.xml` + `stringResource(Res.string.x)`；构建期代码生成 | ✗ |
| B. **纯 Kotlin 自建**（`Str` key + 每语言 catalog）+ app 层 Compose 胶水 | 无代码生成，任何层可用，可单测 | ✓ |
| C. moko-resources / ICU4J MessageFormat | 引入第三方 | ✗ |

**选 B**，理由：

1. A 的 `stringResource` 是 `@Composable`，非 composable 场景只有 suspend 的 `getString(ResourceEnvironment)`。
   `jdbc / engine / tree` 是纯层，不能用 composable/suspend 资源 API → 会被迫出现「UI 一套、纯层一套」两份文案来源，
   违反「唯一来源」。
2. A 需要 Gradle 资源任务 + XML/复数工具链，收益（多 locale 编译期校验）对本项目（仅 2 语言）不划算。
3. B 是纯 Kotlin，**所有层都能 `import i18n.*`**，可被 `gradle test` 直接覆盖，语言切换只改一个状态，
   与项目「状态即 snapshot」一致。
4. 实现落地时若确认 `components-resources` 仍无人使用，顺手从 `build.gradle.kts` 移除该依赖。

## 4. 结构

```
src/main/kotlin/
├── i18n/                     # 纯叶层：只依赖 JDK，禁止 import compose/coroutines/任何上层
│   ├── Lang.kt               # enum Lang { ZH, EN }；fromTag / system() / tag
│   ├── Str.kt                # enum Str { ... } —— key 注册表（唯一来源）
│   ├── CatalogZh.kt          # fun zh(key): String  = when(key) { ... }（编译期穷尽）
│   ├── CatalogEn.kt          # fun en(key): String  = when(key) { ... }
│   └── I18n.kt               # object I18n { @Volatile var lang; fun t(key, vararg args); fun tn(one,other,n) }
└── app/i18n/
    ├── LocalI18n.kt          # staticCompositionLocalOf<Lang> + ProvideI18n + @Composable t(...)
    └── ...
└── app/settings/
    └── LanguagePrefs.kt      # <dataDir>/app.properties 持久化（key = language）
```

- `i18n/` 列入 **纯叶层**（与 `engine` 同级），可被 `engine/model`、`tree`、`db`、`jdbc`、`redis`、`es`、`app` 依赖。
  需同步更新 `AGENTS.md` 的「分层」清单。
- `app/i18n` 是唯一的 Compose 胶水（`CompositionLocal` + 可组合 `t`）。

### Key 命名

- 语义化、按区域分组：`<area>.<element>[.<variant>]`。
- Kotlin 侧以 `Str` 枚举常量承载，如 `Str.TreeGroupTable`、`Str.DialogConnectionTitle`、
  `Str.ToastExportDone`、`Str.TreeLoadingGroup`。
- 占位符统一 `{0}`、`{1}`（只替换 `{数字}`，避免与 SQL/JSON 的花括号冲突）。
- 复数：`Str.XxxOne` / `Str.XxxOther` 两个 key + `I18n.tn(one, other, n)`；中文两个 key 可填相同文本。

### 两语言 catalog 用 `when`（编译期穷尽）

```kotlin
// CatalogZh.kt
internal fun zh(key: Str, a: Array<out Any?>): String = when (key) {
    Str.AppTitle            -> "DB-K"
    Str.TreeGroupTable      -> "表"
    Str.TreeLoadingGroup    -> "正在加载{0}…".with(a)
    Str.ToastExportDone     -> "已导出 {0} 行"
    // ...
}

// I18n.kt
object I18n {
    @Volatile var lang: Lang = Lang.ZH
    fun t(key: Str, vararg args: Any?): String =
        if (lang == Lang.ZH) zh(key, args) else en(key, args)
}
```

- `when` 作为表达式必须覆盖 `Str` 全部枚举 → **漏翻译 = 编译失败**（比运行时兜底强）。
- 少量仍需测试保证的：两语言 `{n}` 占位符个数一致、无空串（见 §8）。

## 5. 运行期与重组（即时切换）

- 语言状态在 `Main.kt`：`var language by mutableStateOf(Lang.system())`。
- 切换动作：`language = new` → `I18n.lang = new` → `LanguagePrefs.save(new)`。
  - **顺序**：先改 snapshot 状态触发重组，再（或同时）写 `I18n.lang` 全局；纯层读取以 `I18n.lang` 为准。
  - 纯层在 UI 渲染路径上**即时**调用 `I18n.t`，所以只要渲染路径在语言变化时重跑，就一致。
- 主窗口与设置窗口是**两棵 composition**，两处都要 `ProvideI18n(language)` 包裹。

### 关键纪律：派生/缓存模型只存 key，不存已翻译文本

即时切换能否做干净，取决于此。反例（现状）：

- `TableDdlRequest.noun: String`（存了 "表"）→ 改成存 `ObjectKind`（或 `Str`）。
- `tree/DbTreeModels` 的组行 `name = kind.displayNoun` → 改成存 `labelKey: Str` + `labelArgs`，UI 渲染时 `t(...)`。
  - 好处：语言切换触发重组时，行只是重新 `t` 一次，无需重建整棵树。
  - 备选（若某处改造代价大）：把该派生计算 `remember(language)` / `key(language)`，语言变化时整体重算。
  - **实际落地**：树行由 `AppBody` 每次重组重算（`buildTreeRows` 内直接 `I18n.t`），语言切换即刷新，无需额外改造；
    只有跨组合存活的**状态对象**（如 `TableDdlRequest`）存 `Str` key。
- `ObjectKind.displayNoun` 删除，改 `ObjectKind.nounKey: Str`（engine 只给 key，不产出译文）。

纯层**即时抛给 UI 的文案**（如 `RowUpdater` 异常、`CELL_TRUNCATION_MARKER`）不需要缓存，
直接在产生点调用 `I18n.t` 即可（异常不会在切换语言后存活；截断标记随结果重建）。

## 6. 持久化与设置

- 语言属「应用级全局偏好」→ 按 AGENTS「持久化分层」走 **properties**，不落 SQLite。
- 文件：`<dataDir>/app.properties`，key `language = zh|en`。
  - 不复用 `app-settings.properties`（那是 `AppPaths` 启动引导用的 `debugHome`，语义不同；
    该文件在 `dataDir` 确定之前读取）。后续新增 app 级标量偏好都并入 `app.properties`。
- 设置窗口「通用设置」新增「语言 / Language」下拉：`跟随系统 / 简体中文 / English`。
  - 「跟随系统」= 不写死；启动时 `Lang.system()`。选择后立即应用 + 持久化。
- 启动顺序：`main()` 首条日志之后、构建 UI 之前：
  `I18n.lang = LanguagePrefs.load() ?: Lang.system()`，并把它作为 `language` 初始值。

## 9. 风险与注意事项

1. **缓存译文不刷新**：任何 `remember` 的派生串若含译文，语言切换后不更新 → 必须按 §5 存 key，
   或把该计算 key 到 `language`。
2. **两棵 composition**：设置窗口是独立 `DialogWindow` + 独立 `MaterialTheme`，别忘 `ProvideI18n`。
3. **顺序竞态**：`I18n.lang` 与 snapshot `language` 要一起更新；若先重组后写全局，会有一帧旧语言。
4. **占位符与花括号**：只替换 `{\d+}`，不要用 `MessageFormat`（会与 JSON/SQL 的 `{}` 打架）。
5. **品牌名/缩略语不译**：PostgreSQL、SQL、Ctrl、F5、Redis 命令、字段名等保持原样。
6. **字体/排版**：中英混排走默认 UI 字体；`EditorSettings` 的编辑器字体/字号不受语言影响。
7. **不翻译日志**：日志是开发诊断，保持现状（便于 grep、与历史日志一致）。
